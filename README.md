# 작전명문 공연 예매

밴드 반송(작전명문) 연례 공연의 온라인 예매·입금 확인·QR 검표·환불을 처리하는 웹앱입니다.
운영 주소는 https://www.band-bansong.life 입니다.

- Next.js 14 (App Router) + Tailwind
- Prisma + PostgreSQL (운영은 Supabase)
- 일반 사용자는 카카오 로그인, 관리자는 ID/비밀번호 로그인. 로그인 토큰은 직접 서명하는 JWT입니다.
- 배포는 Vercel

## 흐름

1. 관객이 카카오로 로그인하고 예매합니다. 1인 1매이고, 예매할 때 **입금자명**(관람객 실명)을 적습니다.
   예매하면 `PAYMENT_PENDING`(입금 대기) 상태가 됩니다.
2. 관객이 입금 기한(기본 24시간) 안에 안내된 계좌로 입금합니다. 기한이 지나면 예매가 `EXPIRED`로 바뀌고 좌석이 풀립니다.
3. 관리자가 입금을 확인하면 `CONFIRMED`가 되고 QR 티켓이 발급됩니다. 은행 앱의 입금 내역을 붙여 넣으면
   입금자명·금액이 맞는 예매를 골라 한 번에 확인할 수 있습니다.
4. 공연 당일 관리자 페이지의 카메라로 QR을 찍어 입장 처리합니다.
5. 환불은 관객이 '내 티켓'에서 요청(`REFUND_PENDING`, 이때 좌석이 풀림)하고, 관리자가 송금 후 '환불 완료'를 누릅니다.

## 공연 관리

공연 정보(제목, 일시, 장소, 관람료, 입금 계좌, 정원, 셋리스트·판매 안내)는 코드가 아니라 DB에 있습니다.
관리자로 로그인한 뒤 **관리자 > 공연 관리**(`/admin/shows`)에서 공연을 등록하고 고칩니다.

- 공연마다 상태가 있습니다.
  - **준비 중**: 어디에도 보이지 않습니다.
  - **판매 중**: 첫 화면(`/`), 공연 안내(`/show`), 예매(`/book`)에 나오고 예매를 받습니다. 한 번에 하나만 둘 수 있어서,
    다른 공연을 판매 중으로 바꾸면 지금 판매 중인 공연은 자동으로 지난 공연이 됩니다.
  - **지난 공연**: 지난 공연(`/past`)에 나옵니다. 예매는 받지 않습니다.
- 새 공연을 등록하면 가장 최근 공연의 장소·입금·판매 안내가 미리 채워집니다.
- **티켓 오픈 일시**를 정해 두면 그 전에는 예매 버튼 대신 남은 시간이 보이고, 시각이 되면 버튼이 저절로 열립니다.
  비워 두면 판매 중으로 바꾸는 즉시 예매를 받습니다. 공연이 시작한 회차는 예매가 닫힙니다.
- **입금 기한**은 '예매 후 몇 시간'으로 정합니다(기본 24, 0이면 공연 시작 때까지). 공연 시작 시각을 넘기지는 않습니다.
- **크레딧**은 한 줄에 `파트: 이름, 이름`으로 적습니다. 공연 안내·지난 공연의 크레딧 탭에 나오고,
  관객은 예매할 때 '관심 있는 공연자'를 이 명단에서 고릅니다(명단이 비어 있으면 직접 적습니다).
- **셋리스트**는 표로 적습니다. 묶음(1부·2부)마다 곡명·아티스트와, 곡마다 파트별로 무대에 서는 사람을 적습니다.
  파트 열은 크레딧의 파트를 따릅니다. 엑셀·구글 시트에서 표를 복사해 곡명 칸에 붙여 넣으면 한 번에 채워지고,
  첫 줄이 `곡명 | 아티스트 | 보컬 …` 같은 제목 줄이면 그 이름대로 열을 맞춥니다. 공연정보 글에 `# SETLIST 1부` 아래
  `1. 곡명 - 아티스트`로 적어 둔 셋리스트는 버튼 하나로 옮겨 올 수 있습니다.
  지난 공연에는 늘 보이고, 판매 중인 공연에는 '판매 중에도 셋리스트 보이기'를 켰을 때만 보입니다(스포일러 방지).
  관객은 셋리스트 탭에서 공연자를 눌러 그 사람이 나오는 곡만 볼 수 있습니다.
- 예매 기록이 있는 공연은 지울 수 없습니다. 지난 공연으로 바꿔 두세요.
- 긴 안내문은 빈 줄로 묶음을 나누고, 묶음 첫 줄을 `# 제목`으로 쓰면 소제목이 붙습니다.
- 포스터는 공연 수정 화면에서 **이미지 올리기**로 올립니다(4MB 이하 PNG·JPG·WEBP, 세로 3:4 권장). 이미지는 DB에 저장되고
  `/api/assets/…` 주소로 나갑니다. 외부 이미지 주소를 직접 적어도 됩니다.
- 시드는 작전명문 1~4를 지난 공연으로 넣습니다. 4회는 2026년 공연 안내에 실렸던 내용(셋리스트 포함, 곡별 크레딧은 비어 있음)이고, 1~3회는 제목·연도와
  임시 포스터(`public/posters/`)만 있으니 관리자 화면에서 채워 주세요. 5회 틀에도 임시 포스터가 들어 있습니다.
- 지난 예매 기록을 지우려면 `docs/supabase-reset-sales.sql`을 Supabase SQL Editor에서 실행합니다.

## 로컬 실행

```bash
cp .env.example .env          # 값 채우기 (아래 표)
npm install
docker compose up -d          # 로컬 Postgres. Supabase를 쓰면 생략
npm run prisma:deploy         # 마이그레이션 적용
npm run prisma:seed           # 역할, 관리자 계정, 비공개 공연 틀 생성
npm run dev                   # http://localhost:3000
```

실제 카카오 로그인을 내 컴퓨터에서 시험하려면 카카오 개발자 콘솔 > 카카오 로그인 > Redirect URI에
`http://localhost:3000/api/auth/kakao/callback`을 더 등록하고, `.env`의 `APP_URL`을 `http://localhost:3000`으로 둡니다.

## 환경변수

| 이름 | 설명 |
| --- | --- |
| `DATABASE_URL` | 앱이 쓰는 DB 주소. Supabase는 트랜잭션 풀러(6543) + `pgbouncer=true&connection_limit=1` |
| `DIRECT_URL` | 마이그레이션용 DB 주소. Supabase는 세션 연결(5432) |
| `APP_URL` | 서비스 주소(끝에 `/` 없이). 카카오 Redirect URI가 `APP_URL/api/auth/kakao/callback` |
| `JWT_SECRET` | 로그인 토큰 서명 키. 32자 이상 무작위 문자열. 없으면 로그인이 동작하지 않습니다 |
| `CRON_SECRET` | DB 깨우기 주소(`/api/cron/keepalive`)를 Vercel Cron만 부를 수 있게 하는 값. 32자 이상 무작위 문자열. 운영(Production)에만 넣으면 됩니다 |
| `KAKAO_CLIENT_ID` / `KAKAO_CLIENT_SECRET` | 카카오 REST API 키 / Client Secret |
| `KAKAO_LOGOUT_REDIRECT_URI` | 카카오 로그아웃 뒤 돌아올 주소. 카카오 콘솔에 등록 필요 |
| `SEED_ADMIN_USERNAME` / `SEED_ADMIN_PASSWORD` | `npm run prisma:seed`가 만드는 관리자 계정(비밀번호 10자 이상). 시드 때만 필요 |

`JWT_SECRET`을 바꾸면 기존 로그인은 모두 풀립니다.

## 배포 (Vercel + Supabase)

1. Supabase에서 프로젝트를 만들고(지역은 **서울**) 연결 문자열 두 개를 받습니다.
2. 내 컴퓨터에서 `.env`에 그 값을 넣고 `npm run prisma:deploy`, `npm run prisma:seed`를 실행합니다.
3. Vercel 프로젝트 환경변수에 `DATABASE_URL`, `DIRECT_URL`, `APP_URL`, `JWT_SECRET`, `CRON_SECRET`, 카카오 값 3개를 넣습니다.
4. 카카오 개발자 콘솔에 Redirect URI와 로그아웃 Redirect URI를 등록합니다.
5. Vercel이 배포하는 브랜치에 푸시합니다. 빌드는 `prisma generate && next build`입니다.

Vercel 서버 지역은 `vercel.json`에서 서울(`icn1`)로 고정합니다. 기본값(미국 동부)으로 두면 서울 DB에 한 번 물을 때마다
태평양을 왕복해서 관리자 화면이 몇 초씩 걸립니다. DB 지역을 바꾸면 이 값도 같은 곳으로 맞추세요.

Supabase 무료 플랜은 7일 동안 DB에 요청이 없으면 프로젝트를 일시정지합니다. 그래서 `vercel.json`의 `crons`로
Vercel이 매일 한국 시간 새벽 3시 무렵 `/api/cron/keepalive`를 불러 DB를 한 번 가볍게 읽습니다(Hobby 플랜은 하루 한 번까지, 시각은 그 한 시간 안 어딘가).
잘 돌고 있는지는 Vercel 프로젝트 > Settings > Cron Jobs에서 볼 수 있습니다. 그래도 판매 시작 전에는 Supabase 대시보드에서 한 번 확인하세요.

## 알아둘 점

- 예매는 회차 행을 잠그고(`SELECT ... FOR UPDATE`) 처리해서, 동시에 몰려도 정원과 1인 1매를 넘지 않습니다.
- 입금 기한이 지난 예매는 따로 도는 예약 작업 없이, 좌석을 세거나 예매 목록을 열 때 `EXPIRED`로 바뀝니다.
  기한 안에 입금했는데 늦게 확인했다면 관리자 첫 화면의 '기한이 지나 만료된 예매'에서 **입금 확인(되살리기)**를 누릅니다.
  그사이 좌석이 다 찼거나 같은 관객이 다시 예매했으면 되살리지 않습니다.
- 입금하지 않은 예매는 관리자가 사유를 적어 취소할 수 있습니다. 사유는 관객의 마이 티켓에 보입니다.
- 입금 확인을 완전히 자동으로 하려면 PG(결제대행) 계약이나 은행 API가 필요한데, 둘 다 사업자등록이 있어야 합니다.
  그래서 입금 내역 붙여넣기로 맞추는 방식을 씁니다. 이름은 공백을 무시하고 비교하고, 금액이 다르거나
  같은 입금자명 예매가 여럿이면 고르지 않고 알려 줍니다.
- 관리자 계정은 카카오로 로그인할 수 없고, 일반 계정은 ID/비밀번호로 로그인할 수 없습니다.
- 입금 확인, 운영진 취소, 검표, 환불·되돌리기, 공연 등록·수정·삭제는 `AuditLog` 테이블에 남습니다.
- 관객이 환불을 잘못 요청했으면 관리자 > 환불 관리의 **요청 되돌리기**로 예매 완료로 돌립니다(좌석이 남아 있을 때). 공연이 시작한 뒤에는 관객이 직접 환불을 요청할 수 없습니다.
- 입장 확인은 판매 중인 공연의 티켓만 받습니다(작년 공연 QR로는 들어올 수 없다).
- 카카오 로그인은 state 값으로 시작한 브라우저와 돌아온 브라우저가 같은지 확인하고, 로그인 토큰은 주소가 아니라 잠깐 쓰는 쿠키로 넘깁니다(남이 만든 링크로 로그인을 바꿔치기하지 못하게).
- 운영진 로그인 토큰은 12시간, 관객은 7일 동안 유효합니다. 로그아웃은 이 브라우저에서 토큰을 지우는 것이라, 이미 새어 나간 토큰을 서버에서 끊지는 못합니다.
- 관리자 화면의 날짜 칸은 관리자 컴퓨터의 시간대와 상관없이 한국 시간으로 읽고 씁니다.
